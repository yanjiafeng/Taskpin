任务详情 · 评论/执行按钮区布局 Demos（PC）

针对「发表评论 / ▶执行·kimi / 💬问答·kimi / ⚙更换」挤在一行的问题，4 个排布方向。每个都是详情抽屉右下角的真实比例模拟（560px 宽）。回复编号即可，例如「按钮选 B」。

A · 两行分组

第一行只做评论（📎 + 发表评论）；第二行虚线隔开，专放执行（▶ 执行 · kimi / 💬 问答 · kimi / ⚙ 更换）。职责最清晰，不再挤；代价是多占一行高度。

执行 用上次的模型/思考/权限直接拉起

B · 输入框内嵌主按钮 + 执行工具栏

「发表评论」收进输入框右下角（类似 GitHub 评论框）；输入框下方一条虚线工具栏专门承载执行：agent 胶囊标签 + ▶/💬/⚙。评论操作与执行操作物理分区，主按钮离光标最近。

C · Split button（一行搞定）

仍然只有一行：左侧 📎 + 发表评论；右侧是一个拆分按钮——主区「▶ 执行 · kimi」直接跑，箭头展开下拉（问答 · kimi / 更换工具/参数）。最省空间，PC 常见范式；下拉项少，学习成本低。

💬 问答 · kimi只讨论不实现，用上次参数
⚙ 更换工具/参数…打开选择面板（codex / reasonix / dsh）

D · 图标执行组（最紧凑）

一行最紧凑形态：左侧 📎 + 发表评论；右侧「kimi：」小标签后跟三个圆形图标按钮（▶ 执行 / 💬 问答 / ⚙ 更换），悬停显示说明。占位最少；代价是图标不如文字直白。
